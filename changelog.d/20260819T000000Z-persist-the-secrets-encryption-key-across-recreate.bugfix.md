Mill's at-rest secrets key is now persisted beside `config.json` instead of being derived from the machine hostname. In a container `os.uname().nodename` is the container ID: stable across a restart, but not across a recreate — and every image update recreates. An update therefore left the config file intact and readable but undecryptable, so mill came up with no OpenRouter key and no GitHub App, logged both credentials as unset, and every ticket blocked on `OPENROUTER_API_KEY is not set` or `forge auth not configured` until the secrets were restored by hand. The key now lives on the same volume as the config it protects, created 0600, and a block that only decrypts under the old hostname key is re-encrypted under the persisted key the first time it is read — which has to happen while that hostname is still current, because a recreate destroys the old key for good. Environments with no writable config directory keep working through the legacy derivation.
