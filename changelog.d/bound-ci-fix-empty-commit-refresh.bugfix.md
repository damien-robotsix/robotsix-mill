`ci_fix` no longer livelocks on a genuinely failing CI. When the rebase was a no-op the stage pushed an empty commit to force a fresh CI run — reasonable for a stale or flaky run — and then read the check status about two seconds later. The run it had just triggered was necessarily still `queued`, so the status came back `pending` and the stage returned to `implement_complete` without ever reaching the fix path below it. Every subsequent entry into `fixing_ci` did the same thing, so a real failure was refreshed forever and never diagnosed: on `robotsix-auto-mail` ticket `…-6a4e` this cycled for hours (each pass returning in under 10 seconds) while the fix agent ran zero times. The refresh is now bounded — one per failure, reset on genuine forward progress — and the stage returns immediately after pushing rather than reading a status it just invalidated. Once the budget is spent it falls through to the real status, so a failure that survives a fresh run reaches the fix agent.
