Add a scope-assessment gate to `POST /tickets/ingest`: a cheap small-tier classifier judges whether a newly-ingested report is a single focused task or multi-concern work. Clearly multi-concern reports are auto-promoted to an epic and decomposed into dependency-ordered child tickets via the existing epic-breakdown machinery, with the decision and rationale recorded in ticket history. The gate is conservative (borderline reports stay single tasks), toggleable via `MILL_AUTO_EPIC_ENABLED`, thresholded via `MILL_AUTO_EPIC_MIN_CONFIDENCE`, and runs past all dedup checks so re-ingest stays idempotent.
