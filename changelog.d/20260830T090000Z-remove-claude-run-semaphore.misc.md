Removed the process-wide Claude run semaphore (`agents/claude_concurrency.py`). It was added in June 2026 to smooth a startup "spawn storm" of `claude` CLI subprocesses, but with nearly every agent on Claude tiers a 30-minute opus implement run held one of the `claude_max_concurrency` slots for its whole duration and every short Claude call — gates, classifiers, dedup, review, the ingest route's inline classifiers — queued behind it; on 2026-08-30 `POST /tickets/ingest` hung for minutes because five implement sessions saturated the three slots. `build_agent` and `build_subagent` now return the Claude provider handle directly; the real limits are the subscription rate cap (park logic) and host resources (`max_global_concurrency` + sandbox caps, plus `startup_jitter_seconds` for the boot fan-out). `claude_max_concurrency` stays as a documented inert field because the deployed config pins it and `PUT /config` rejects unknown keys.
