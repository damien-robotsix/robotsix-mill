Add `parked_rebase_cooldown_hours` config (default 4) to throttle continuous re-rebasing of PRs parked in `human_mr_approval`. A `last_rebase_at.txt` timestamp artifact is written after each successful rebase. When a parked PR conflicts or falls behind the target within the cooldown window, the ticket stays in `HUMAN_MR_APPROVAL` instead of cycling through `IMPLEMENT_COMPLETE` → `REBASING`. Setting `parked_rebase_cooldown_hours=0` disables the feature (pre-existing behaviour). The `_poll_implement_complete` path is unchanged.
